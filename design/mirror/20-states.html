States & announcements

Where a product stops feeling finished, and always the part left out of a design file. Specified here because this codebase has two recurring bugs that are design problems before they are code problems.

1 · Loading — content uses a skeleton

The section header renders immediately; only the body waits.

Content loads with a skeleton in the shape of the content. An action spins. The skeleton reserves the exact row grid so nothing jumps when data lands — a table that reflows on arrival is how a trader mis-clicks a position. A spinner attaches only to a control the user pressed:

An empty state names what is absent and offers the one action that fills it. “Clean session” earns a green tick because zero alerts across eight trades is genuinely the good outcome. An empty state never takes an error colour and never gets a retry button; if there were something to retry, it was not empty.

3 · Error — always distinguishable from empty

⚡

You are offline

Showing the last snapshot from 13:41. Prices and P&L are frozen until the connection comes back.

reconnecting · attempt 3

Three things an error state must carry: what failed in the user's language, whether their data is at risk, and a way out. The endpoint and timestamp sit in an inset well in mono — a trader will paste that line into a support email and it saves a round trip. Offline is an error, not an empty, and it names the snapshot on screen, because a frozen P&L presented as live is the most expensive lie this interface could tell.

4 · Degraded — the page works, one guarantee does not

Prices are delayed. The market-data feed dropped at 13:38. P&L below is computed from the last tick received, not live. Details
Syncing your trades. 142 of 380 fills imported. Analytics will be incomplete until this finishes. 42%
Demo mode — showing sample data. Nothing here is your trading. Connect Zerodha to replace it. Connect Zerodha

Degradation is announced inline, above the thing that is degraded, never as a toast. A toast saying prices are stale is gone by the time the trader looks at the price. The banner stays as long as the condition does, and states the consequence (“computed from the last tick”) rather than the cause (“websocket disconnected”).

5 · Announcements — the live-region spec

Alerts arrive over WebSocket with no user action. Nothing on screen has focus, so a screen reader is told nothing at all.

SeverityRegion Announced string
criticalaria-live="assertive"
role="alert"		 “Critical. Daily loss limit breached. ₹25,000 of ₹25,000 used.”
dangeraria-live="assertive"
role="alert"		 “Danger. Size escalation. BANKNIFTY entry 4 times your average size.”
cautionaria-live="polite"
role="status"		 “Caution. Early exit. NIFTY CE closed after 8 minutes.”
infonot announced Visible only. Announcing every info event is how a user turns the app off.

Severity, title, and one clause of reason — nothing else. The full alert body runs to three sentences and carries five figures; read aloud on arrival it buries the one word that matters. The detail stays on screen for the user to navigate to.

The region is a single persistent node, emptied and refilled. Appending to a live region re-announces everything already in it. And a live region must exist in the DOM before the content is written into it, or nothing is spoken at all — which is the failure mode that makes this bug invisible in testing.

Rate-limit to one announcement every 3 seconds, coalescing the rest into “3 more alerts”. During a tilt sequence the engine can fire several detectors on a single fill, and a screen-reader user should not be read a paragraph mid-trade.

The two rules

A failed request is never rendered as an empty state. Empty means the server answered and the answer was nothing. Error means the server did not answer. Those are different facts and a trader acts on them differently — one says “you had a clean session”, the other says “you do not know what your session was”. Any component that can show both takes them as separate props, never as one nullable array.

If a section has a header, the header renders even when the body cannot. The nastier version of the same bug: a component that returns null when its data is missing, so a failed request renders as nothing at all — no header, no space, no trace. That is worse than a wrong empty state, because there is nothing on screen to be suspicious of. It has already happened here twice.
